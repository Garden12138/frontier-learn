# 第一次实际试用：Self-Attention → MHA / MQA / GQA

默认先执行 **A：无付费模型基础试用**，用两次各约 30 分钟体验完整的记录与复盘流程。
B 是另行配置模型后的可选试用，C 是真实 GitHub App/PR 试用；三者分别填写结果。
没有完成的步骤保留“未试/阻塞”，不要用自动化测试替自己作答。

## A. 无付费模型基础试用

### 第一轮：旧笔记 → 画像 → 目标计划 → 第一次会话

1. Web“知识来源”填写仓库与上面推荐主题目录，勾选只读同意，添加来源后点“同步笔记”。
   展开文件范围/状态，记录成功、部分失败或具体错误。代码仅按文本处理，不执行。
2. 同步成功后到“知识画像”，搜索“自注意力”“MHA”，展开 2–3 条证据。
   人工检查摘录、commit SHA、文件行号是否对应原文，状态应保守；
   没有 MQA/GQA 或术语同义词未合并时保留未知，不手工伪造自动识别成功。
3. “学习目标”创建“理解 Transformer Self-Attention，并进一步学习 MHA、MQA、GQA”，
   每日 30 分钟，方向填“自注意力, MHA, MQA, GQA”，自评可不选。
   如果希望固定顺序，在“时间与先修方向”自行记录顺序；系统不会验证其专业正确性。
4. “今日学习”生成计划，查看并采纳首个可执行任务，记录计划版本、建议理由、证据 ID。
   如果只看到模板化步骤，记录体验；当前确实是本地规则规划。
5. 打开 [Attention Is All You Need 摘要](https://arxiv.org/abs/1706.03762)，
   阅读摘要、选一段正文，点击工具栏→“分析当前页”。确认显示“仅摘要”，选择“直观解释”，
   关联上述目标/任务，确认本地保存→“保存并开启导学”。
6. 等待 Worker 完成，观察阅读方法、引用和“本地规则建议”标签。在 Web“导学会话”打开同一条。
   追问选择片段并保存一个问题，确认历史保留。**A 模式不会提供真实 AI 概念答案**。
7. 用自己的话在草稿纸回答：“Self-Attention 在当前材料中提出了什么？摘要能否支持实现细节？”
   再回原页检查。若需具体数学推导，应另读笔记/论文正文，不能让摘要替代。
8. 在会话点“开始短测”，自行选择来源边界题答案，阅读评价后再确认证据；
   “生成笔记草稿”，到“笔记审核”补充自己的理解、来源、未知处并下载 Markdown。
   记录这个测验只证明来源边界，不能写成自己已掌握 Self-Attention。

**同步失败的可完成回退：** 保留失败 Job/错误码。无凭据 API 曾限流，容器 DNS 曾触发
`UNSAFE_URL`。先看 [诊断](../testing/v0.1.1-user-trial.md#github-连接诊断与人工解除步骤)，
不要关安全校验或连续重试。
可以不依赖知识画像，先从第 3 步创建目标；在浏览器手工打开仓库中的
`Implement self-attention.md`，或阅读本仓库
[固定公开快照](../../services/api/tests/fixtures/real-notes/self-attention.txt)，
只复制一段已读、超过 40 字的原文到插件“使用手工粘贴文本”预览并保存。
注明原 URL/章节、固定快照或手工来源。该路径能体验会话/短测/草稿，但不能计为 GitHub
导入/画像/行号验证通过。手工材料“来源未经核验”是预期提示。

### 第二轮：GQA → 解释与反例 → 新证据 → 下一轮计划

1. 使用同一账号/目标。“今日学习”查看当前计划版本。如果 GQA 不在今日任务，
   从长期方向查看，或“插入临时兴趣内容”建立“阅读 GQA §2.2”，填下面的材料 URL。
2. 打开 [GQA 论文 HTML §2.2](https://arxiv.org/html/2305.13245v3#S2.SS2)。
   选一段可见正文 →重新点击插件工具栏→分析。确认 HTML 解析范围、选区、截断信息；
   点“回到原文”人工检查定位。此页属于试用材料，本轮固定公开页面自动检查不含它，
   历史准备检查曾通过；当前网络/结构变化仍需本人确认。
3. 选择“深入原理”，关联目标与 GQA 任务，确认保存，等本地规则导学完成。
   若 HTML 不可读，打开 [摘要](https://arxiv.org/abs/2305.13245) 或手工粘贴实际已读段落；
   数学式/图表去原页查看，不根据抽取缺失部分猜答案。
4. 遮住原文，独立回答下面三题，保留第一次答案：
   - GQA 中什么被共享？MHA、MQA 与 GQA 如何比较？
   - 8 个 query heads、2 个组时，你怎样画出共享关系？改成 1 组/8 组会怎样？
   - 减少 KV 数据为什么不等于所有硬件、任务都有相同加速比？
5. 回 §2.2、图示和实验条件核对，记录“独立说明/查原文后纠正/仍不确定”。
   此处由你人工评估，系统当前不会独立给开放题打分。
6. 在导学会话完成另一道来源边界题，确认后生成/编辑/下载草稿。
   把自己的答案、纠正和依据写进草稿，保留不确定性。不要在 A 中开启概念拟题或 PR。
7. 回“今日学习”点“根据最新证据重新规划”，查看计划历史。
   记录前后版本、测验/证据 ID、推荐理由，以及下一步是否更合适。
   当前计划按实际保存的 LOW 边界题结果调整；你在 Markdown 里写的人工概念评价不会自动被独立评分。

应该观察：是否容易找到下一步、证据能否回原文、计划是否解释清楚、插件是否打断阅读、
短测和笔记是否帮助发现未知、第二轮计划是否可执行。不要只统计按钮能否点击。

## B. 配置真实模型后的 AI 导学试用

这一步可能收费，不属于默认 A；本轮没有替你调用。
由你按 [模型接入说明](../production-integrations.md#openai-导学) 在服务端配置 key/model 和低预算，
API/Worker 使用一致配置，再重新创建一个会话。
“设置与数据”全局同意后，每轮另行勾选只发送最小片段。检查内容标为“模型解释/推测”，
引用能回到材料；追问不同层级，核对真实答案正确性与遗漏。

可选生成概念选择题：明确章节/选区、同意本次云处理；先作答后看 rubric/答案依据，
人工核对是否多解/矛盾，再决定是否确认证据。试一次取消→重新同意→新任务恢复，
不超过三次拟题。记录供应商实际用量与本地预留的区别，答对仍不算掌握。
不满意时撤销云授权并回 A，避免扩大费用。

## C. 配置真实 GitHub App 后的 PR 写回试用

需要真实 App、服务端加密密钥及你对目标仓库的写权限，默认写回关闭。
先在自己专门的测试笔记仓库或明确确认的非空测试目录试用；不要首次覆盖 notes 的既有正文。
按 [GitHub 配置](../production-integrations.md#github-app) 授权单一仓库；
独立确认写目录 →笔记审核保存草稿 →选新文件路径 →预览 Diff →再次确认 →创建 PR。
人工在 GitHub 核查新分支只含批准内容；确认后自行合并，再回应用核对/重新索引。
记录撤销、冲突或失败是否保留草稿。本轮自动化仅模拟 PR，不能填成此路径已通过。
