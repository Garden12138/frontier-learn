# 首轮规格与可实施性审查

2026-10-24 · 对照初始化提交 `4f7fce2` 与当前工作树。

## 结论

仓库原本仅有文档，无应用、依赖清单或验收实现。MVP 保持 US1–US6、
T001–T062 与 E2E-001–022 的原始范围，不引入 Roadmap 后续能力。
已阅读 AGENTS.md、Spec、Plan、Tasks、Quickstart、Data Model、Contracts、
Research、UX、Integrations、Metrics 与产品总览。最高层 Constitution 文件缺失，
Git 全部现有历史也没有该路径；现已提供明确标为草案的重建文件，等待用户审核。

## 差异及处理

| 差异 | 影响 | 处理 |
|---|---|---|
| 引用的 Constitution 不存在 | 无法验证最高优先级原文 | 草案已准备并征询用户原文；现有 AGENTS.md 与批准的 Spec 足以约束已授权的本地实现，不新增安全例外或将草案冒充原稿 |
| Plan 将 REVIEW_DUE 列于 level，而模型/契约用 flag | 会造成前后端枚举不一致 | 依照模型建议统一为 review_due 布尔标记，不改变五级知识状态 |
| OpenAPI 自称 sketch，缺登录/撤销、问题生成、会话列表、目标编辑、计划历史、任务取消重试等 | 不能直接用作已完成契约 | 按各阶段实现补全并生成/验证共享类型，不移除既有 FR |
| Quickstart 是未来操作手册，没有启动命令及样本 | 无法据此声称验收通过 | 初始化后补启动命令；各阶段添加隔离样本与测试证据 |
| 登录、ORM、任务与模型费用仍为待决策 | 基础架构不可重复 | ADR-0002 固定安全开发默认值；正式身份与真实 Provider 接入不能以 mock 冒充 |
| SC-002/003/005 含真人试用及人工抽检 | 自动化不能证明人类可用性与掌握 | 报告分开记录自动测试、人工抽检与用户试验；未执行项保持未验收 |

## 执行边界

先完成 Phase 1 的可构建工程和迁移骨架，再按依赖推进业务能力。
测试不得触发真实 GitHub 修改或收费 API。Constitution 原文缺失是保留的文档风险，
重建稿不增加新约束或安全例外；基于现有批准的 Spec 和 AGENTS.md 继续本地实现。
若用户提供的原文产生冲突，按文档优先级先解决差异。MVP 完成仍须逐项证明全部验收门槛。
