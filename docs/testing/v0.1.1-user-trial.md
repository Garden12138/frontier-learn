## GitHub 连接诊断与人工解除步骤

1. 在知识来源和设置与数据读取具体 Job 错误；`GITHUB_RATE_LIMIT` 表示外部配额，
   遵守 reset/Retry-After，过期任务应新建同步，不连续点击重试。
2. `UNSAFE_URL` 可发生在 HTTP 前：历史容器 DNS 返回非公网 IPv6，而宿主机解析不同。
   核对 Docker/OrbStack 与 VPN/代理的 DNS；不关闭 SSRF、固定 GitHub IP 或放行非公网地址。
   本轮不修改用户全局网络设置。修复网络后再作一次有界只读同步。
3. ChatGPT 连接的 GitHub 工具和 FrontierLearn 本机 App 是两个独立授权，不能互相转交凭据。
   未配置 App 时公开仓库仍可只读连接，但受未认证 API 配额约束。
4. 需要 App 时按 [服务接入](../production-integrations.md#github-app) 配齐服务端配置组，
   本地回调 `http://127.0.0.1:18000/api/v1/github/callback`，Web origin 为
   `http://127.0.0.1:5176`。保留既有加密密钥和备份；勿把 token/恢复码放在聊天或网页。
5. 先只读选择小目录；同账号同仓库只有一来源，修改范围会撤回范围外证据，
   不能通过轮流改范围伪装累计整库导入。失败时使用 FIRST_TRIAL 的手工片段流程，
   它不代表 GitHub 同步通过。

历史小目录 2 Markdown/8 GET 成功、两次完整目标目录限流及容器安全拒绝，均是当时观察，
不是当前网络保证。真人样本 0、付费模型调用 0、真实 PR 写回 0；仅本人填写反馈后计入真人验收。
