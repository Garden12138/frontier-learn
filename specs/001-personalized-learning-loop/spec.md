# Feature Specification: 001 · Personalized Learning Loop

**Status**: Approved product baseline; awaiting engineering review  
**Created**: 2026-10-24  
**Target**: First complete MVP (V0.1–V0.5)  
**Related**: [Product Vision](../../docs/product-vision.md) · [Roadmap](../../docs/roadmap.md) · [Constitution](../../.specify/memory/constitution.md)

## 1. Feature Summary / Problem Statement
技术学习者已在 GitHub/博客等存储大量笔记，却在阅读 arXiv/Hugging Face 等新内容时仍不知从何下手；普通 AI 总结缺少用户知识依据，学习成果难以检验，也不能持续更新个人知识库。本功能交付一个用户可控、基于证据、具有完整反馈循环的个人 AI 导师。

### 1.1 目标
- 让用户在已有知识基础上快速找到当前网页学习入口，而非每次从零开始。
- 根据知识证据、目标和反馈生成短期可执行的计划，并可解释推荐原因。
- 通过明确来源、交互问答、理解校验、笔记回写形成跨会话学习成长闭环。
- 在访问受限、导入失败、模型不可用、版本冲突时仍可恢复或安全降级。

### 1.2 非目标（MVP）
- 不开发桌面 App、移动 App、全面 Web 搜索雷达、跨用户社交、课程商城、付费计费。
- 不做无限制的 PDF 数学公式/图表精确识别；先支持结构化网页正文，PDF 只允许显式提示不支持/可选后续模块。
- 不自动执行未知代码、不无审核写主分支、不自动发布博客、不导入用户全部聊天历史。
- 不自动证明人类的认知状态；知识状态是可修正、带证据和不确定性的估计。
- MVP 的 AI 分享支持 ChatGPT **可访问的共享页面**与粘贴文本降级，不保证任何分享 URL 都能抓取。
- 不把最初指定的单个公开仓库或特定职业目标硬编码为系统逻辑。

## 2. Actors & User Journeys

- **Learning User**：拥有或没有现存笔记；确定目标、授予知识源权限、学习、审核成果。
- **AI Tutor**：根据证据与计划组织课程、答疑、出题、生成笔记草稿；无法自行改变安全策略。
- **Data Connector**：在明确授权的资源范围内读取/增量同步/申请写回。
- **Admin/Operator**（MVP 开发/测试使用）：追踪失败、任务成本、回滚及密钥安全，不能擅自读取用户私人原文。

## 3. User Stories & Acceptance Scenarios

### US1 [P1] 导入 GitHub 笔记并构建可解释知识画像（V0.1）
**As a** 学习者，**I want** 指定一个 GitHub Markdown 仓库进行只读分析，**so that** AI 导师能基于旧笔记而非自述安排学习起点。

**Acceptance scenarios**
1. **Given** 用户输入允许访问的仓库 URL，**When** 授权并点击导入，**Then** 系统列出文件范围、同步状态与可撤销的授权，并只抽取支持的 Markdown/代码示例；忽略构建产物、二进制和超限文件。
2. **Given** 具有 BPE/Attention/Agent 笔记的仓库，**When** 索引结束，**Then** 用户能查看知识点卡及对应的源文件路径、引用段落、时间与证据类型。
3. **Given** 有笔记但无测验的知识点，**When** 展示画像，**Then** 状态应为“有学习证据/待验证”，不得标成“熟练掌握”。
4. **Given** 已导入同一提交 SHA 的仓库，**When** 再次同步，**Then** 不生成重复实体；新增/变化/删除文件能被差量处理，删除只影响该来源的证据。
5. **Given** 空仓库、私有仓库未授权或网络超时，**When** 导入，**Then** 提示明确错误与可重试/取消选项；既有数据不被错误覆盖。

### US2 [P1] 基于目标与学习者证据自动生成学习计划（V0.2）
**As a** 学习者，**I want** 告知学习目标、方向、可用时间，**so that** 系统主动规划而不是等待我提问。

**Acceptance scenarios**
1. 用户可设目标（自由文本 + 可选建议）、可用时间、优先方向，允许后来修改。
2. 计划包含长期路线（主题）、阶段任务、当日可行动任务，逐项显示先修知识、预计投入、来源和推荐理由；不提供虚构的真实阅读时长承诺。
3. 已有知识应影响建议路径；不确定的状态通过 1–3 个小测验或用户自报确认，用户可拒绝测试并保留“未知”。
4. 用户可跳过、暂停、重排与临时插入兴趣内容，修改不会永久丢失旧计划历史；至少保存一次计划修订记录。
5. 空知识库的新用户可基于自报或短测验得到可用计划，不应因为 GitHub 未连接而被拒绝。

### US3 [P1] Web 工作台与浏览器插件联动的情境导学（V0.3）
**As a** 学习者，**I want** 在 arXiv/Hugging Face 网页中直接使用侧边栏，**so that** 我知道怎么读、哪里补基础、如何和原文对应。

**Acceptance scenarios**
1. Web 工作台可查看学习目标、画像依据、当日计划、历史导学会话。
2. 用户主动点击插件“分析当前页”后，若站点为支持的 arXiv 摘要/HTML 或 HF 模型页，插件解析标题、正文、章节/来源 URL，并生成短导读、重点、前置知识和学习步骤。
3. 解释页面片段时提供源文锚点或可回到原文的定位；无法定位必须显式提示“引用未验证”，不能伪造原文依据。
4. 导学层级可选“直观解释 / 深入原理 / 工程实践”；同一学习会话可以追问且保持目标、已知知识和当前网页上下文。
5. 用户不授权/域名不支持/网页内容过短时，插件给出安全降级（选中复制、粘贴文本、手工 URL 导入），不可无感读取所有标签页。
6. Web/插件对同一账号的学习计划与导学会话一致；插件注销时无法继续访问私有学习数据。

### US4 [P2] 将 AI 对话共享内容转换为导学任务（V0.4）
**As a** 学习者，**I want** 把一段 AI 对话当作教材，**so that** 对话中的疑问、代码与结论能够转成后续学习计划。

**Acceptance scenarios**
1. 用户粘贴 ChatGPT 公共分享链接，系统检查 URL 合规性并在能获取页面时解析对话角色与正文；无法获取时明确提供手动文本导入路径。
2. 导入结果区分用户问题、AI 回答、代码、未核实结论；不把 AI 答案自动当成可靠事实或用户掌握证据。
3. 系统生成 1–3 个待验证学习问题和相关现有知识点链接，用户可以把它加入或拒绝加入当前计划。
4. 分享内容默认仅用于当前用户的学习库；展示导入内容预览与敏感信息提醒。

### US5 [P1] 理解验证、笔记草稿与安全 GitHub 回写（V0.5）
**As a** 学习者，**I want** 将学习后的验证结果写回原来的笔记库，**so that** 下一次 AI 导学拥有更好的知识证据。

**Acceptance scenarios**
1. 导学完成可发起至少一种短验证（概念解释题/选择题），系统保留题目、用户作答、评价依据、时间及不确定性；答案不是简单 AI 自评百分数。
2. 生成包含来源、当前理解、步骤、限制、未解疑问的 Markdown 草稿；默认**不自动**上传、覆盖或发布。
3. 用户可以预览 Diff，选“新笔记 / 手工合并 / 仅本地保存”；写回采用分支与 PR（或用户主动下载 Markdown）；不得直接改默认分支。
4. 在文件发生冲突、无写入权限、Token 失效时，安全失败，保留草稿并给出重试/取消；不重复开相同 PR。
5. 经用户确认的练习与笔记可以生成新的证据。系统刷新知识状态，并解释某条后续学习建议与上一次结果之间的因果关联。
6. 用户可删除导入来源及其派生学习证据；删除行为不得误删属于其他来源的独立证据或未经授权覆盖外部仓库。

### US6 [P2] 低成本持续使用与故障恢复（跨阶段）
**As a** 学习者，**I want** 任何一次请求失败都不破坏学习状态，**so that** 不依赖稳定网络或特定模型供应商才能持续学习。

**Acceptance scenarios**
1. 外部 API 失败时显示任务状态与可重试入口，任务具有最大重试次数、超时和预算上限。
2. 导入/索引/导学/回写记录结构化状态；失败部分可单独重新执行，成功对象保持幂等。
3. LLM Provider 可替换，测试环境通过 Fake Provider 运行关键验收用例，不需真实付费 API。
4. 用户可导出自己的学习笔记与学习记录，撤销知识源连接及清理本地学习数据。

## 5. Non-Functional Requirements (NFR)

- **隐私/权限**：只读接入为默认；最小 GitHub Repository 权限；写回须明确用户确认和受限仓库范围；敏感正文在模型调用前提示用途与数据处理方向；密钥服务端加密，不存网页 DOM。
- **防护**：所有外部文本均为低信任级，禁止执行其中的指令；URL 导入需要协议、域名、DNS 解析和重定向检查，防 SSRF；HTML 需要严格 sanitization，代码块默认不运行。
- **数据隔离**：每条对象带 `user_id`；后端授权和数据库查询均做用户边界，不能仅依赖前端筛选。
- **可信性**：对来源锚点、引用段落保存偏移或稳定节点标识；“模型生成解释/推测”与“有来源证据”标识不同。
- **性能目标（初步门槛，待真实测量校准）**：测试规模为 200 Markdown 文件 / 10MB 可解析文本；不要求整库实时完成，支持异步任务与渐进结果；已缓存 Web 首屏在标准网络下目标 p95 < 3s；非流式 LLM 总响应受模型/网络影响，界面必须流式或显示明确状态。
- **可靠性**：幂等导入、文件版本校验，重试退避和不可恢复错误归类；所有异步任务有状态与截止时间。
- **无障碍与国际化**：基础键盘导航，中文 UI 首发，保留英文技术术语及原文；设计兼容英文语言包。
- **可观测性**：计量 API 调用成功率、同步失败、令牌使用、学习会话完成率；不记录整段用户私密源文。
- **可扩展性**：源 Connector、LLM Provider 和前端客户端之间通过契约解耦。

## 6. Scope / Dependencies

| Release | Scope | Gate |
|---|---|---|
| V0.1 | GitHub 只读接入 + 知识证据 | 每条画像断言能展开证据来源 |
| V0.2 | 学习目标 + 规划与工作台 | 每条建议可解释，支持无知识库用户 |
| V0.3 | Extension + arXiv/HF 导学 | 至少 10 个不同网页样例、引用可定位 |
| V0.4 | 聊天分享 / 文本导学 | 解析成功/失败/权限限制路径均可用 |
| V0.5 | 测验 + 草稿 + PR 回写 + 重规划 | 完成“旧知识→新学习→新证据→新计划”闭环 |

## 7. Edge Cases

1. 同一 Markdown 改名、移动、删除或多个仓库重复内容：不应盲目累计知识证据。
2. 文档只有目录/链接/代码片段：可以创建低强度证据，不能判定已掌握。
3. 论文含争议或 AI 对话包含明显错误：导学内容需区分来源、解释及待核实推测。
4. 原网页只展示摘要，正文/图表不可获取：必须注明可分析范围。
5. 不支持的分享链接、登录墙、反爬禁止：不绕过访问控制，允许手动导入。
6. 多设备同时修改知识状态/学习计划：使用乐观锁或版本校验，避免最后写入静默覆盖。
7. 用户要求删除数据但外部笔记仍留在 GitHub：分别解释内部删除与外部数据的区别。
8. GitHub PR 可能已创建但异步回调超时：通过 idempotency key / branch 名核查，避免重复创建。
9. 非 AI 学习主题、新用户无存量资产、取消模型使用授权：仍提供基本手动学习路径。

## 8. Success Criteria (SC)

以下是**上线验收门槛/实验指标**，不代表已达到：

- **SC-001**：10 条知识画像样例中，100% 提供有效来源链接或“无可靠依据”标记；不得展示无证据的“已掌握”。
- **SC-002**：至少 80% 的试用者能在 2 分钟内找到一项可执行学习任务（小样本可用性实验，记录样本数）。
- **SC-003**：不少于 10 个 arXiv/HF 页面用例，在结构化可用网页中可展示导学入口；引用锚点经人工抽检正确率 ≥95%。
- **SC-004**：GitHub 增量导入重复执行不重复创建文件/知识证据；版本冲突不会改动默认分支。
- **SC-005**：一位试用者至少完成连续两次学习会话：第二次计划的调整能追溯到第一次的验证结果。
- **SC-006**：访问失败、权限撤销、模型不可用的测试用例，不会泄露密钥，不会丢失已有草稿。

## 9. Open Questions for Engineering Review

均允许先采用显式安全默认值并记录 ADR，不阻塞首轮规格：

1. 初期身份登录：GitHub OAuth 还是邮箱/魔法链接？建议 GitHub 连接作为主要第一入口，但不能把 GitHub 当作学习系统唯一登录选项。
2. 模型费用：BYOK（用户自配 API）还是服务端受控额度？建议开发初期 Fake/开发 API + BYOK 可配置，商业化后再评估额度模型。
3. 源段落引用稳定性：Markdown 文件修改后采用 commit SHA + path + 行号范围；网页采用 canonical URL + DOM 选择器 + 文本片段兜底。
4. 质量评价：自动反馈不是金标准，需用户自评/抽样人工审核/可执行实验共同约束。

## 10. Engineering completion baseline (2026-10-26)

补齐现有 MVP 的正式接入缺口，不扩展未来 Roadmap：独立账号/密码登录与一次性恢复码，
GitHub App 可选连接/仓库选择，服务端 OpenAI Responses Provider（可关闭并回退本地规则）。
Mock 账号不得用于进入真实账号，生产拒绝开发会话；恢复账号撤销旧会话。
用户不需要 GitHub 或模型密钥才能使用学习工作台。GitHub 凭据经服务端 OAuth/App 获取，
只向选定仓库颁发短期只读令牌；写权限仍需单独确认目录与 Diff，不能自动写回。
云模型调用前须有内容处理授权，按用户及部署设置每日请求/令牌预留上限；超限停止，
失败不自动调用付费模型重试。默认无云调用，测试使用假响应，不消耗付费 API。
实际身份恢复、费用边界与授权状态须有可操作 UI、异常/越权/撤销与端到端测试。
工程默认见 ADR-0009，真实服务凭据与真人验收仍与代码交付分开记录。
